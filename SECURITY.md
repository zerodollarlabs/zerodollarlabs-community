# Security reporting

Please do not disclose vulnerabilities or credentials in public issues or Discussions.

Email **zerodollarlabs@gmail.com** with subject `Security report: <tool or website>`. Include the affected version/URL, reproduction steps, likely impact and a minimal safe example. Remove secrets and personal data. We will investigate and coordinate a fix; no response-time commitment or paid bounty is promised.

If private GitHub vulnerability reporting is enabled, use the repository's Security tab. Do not upload app binaries containing personal data or send code-signing certificates/private keys.

Test only systems you own or are authorized to test. Avoid production load tests, social engineering, data destruction and collecting other users' data. A suspected leaked credential should be revoked by its owner rather than pasted into a report.
